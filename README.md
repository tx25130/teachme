# teachme

在项目工作区内系统化地教授用户一项新技能或概念。创建教学目录、设计互动课程、生成参考文档，支持多会话持续学习。

## 何时触发

- 用户说"教我这个"、"我想学 XX"、"能不能系统讲一下 XX"、"帮我入门 XX"
- 用户表现出系统性学习某个主题的意图（如"我想搞懂 XX 原理"、"XX 零基础怎么入门"）

> 该技能为**有状态**技能：用户计划跨多个会话系统学习，学习状态保存在教学目录中的各个文件里。

## 核心理念

深度学习需要三样东西：

| 要素 | 来源 |
|------|------|
| **知识** | 高质量、高可信度的资源（写入 `RESOURCES.md`，禁止依赖模型的参数化记忆） |
| **技能** | AI 设计的、高度相关的互动课程，基于知识进行练习 |
| **智慧** | 与其他学习者和实践者的真实交流（社区） |

同时区分两种学习类型：

- **流利度（Fluency）**：当下快速回忆的能力，易产生"我已掌握"的幻觉
- **存储强度（Storage strength）**：长期保持的能力，才是真正目标

设计课程时用**合意难度**建立长期记忆：检索练习、间隔重复、交错练习。

## 工作区结构

技能运行前会先询问用户想学的主题，并在当前工作目录下创建一个 **kebab-case** 命名的教学目录（如 `python-basics`、`machine-learning`）。该目录即**工作区根目录**，所有教学产物只能存放在其中。

```
<topic>/
├── MISSION.md              # 用户学习此主题的「原因」，所有教学决策的依据
├── RESOURCES.md            # 高可信度学习资源 + 社区列表
├── GLOSSARY.md             # 术语表，课程间统一语言的「词典」
├── NOTES.md                # 草稿笔记：用户偏好与工作备忘
├── QUESTION.md             # 按 lesson 分割的用户提问与解答
├── reference/*.html        # 参考文档：课程内容的压缩精华，适合打印速查
├── learning-records/*.md   # 学习记录（类 ADR），文件名 0001-<slug>.md
├── lessons/*.html          # 课程：主要教学单元，文件名 0001-<slug>.html
├── assets/*                # 课程间复用的组件（样式表、测验组件、模拟器等）
└── harness/                # （可选）锁定协议产物：ADR + 验证脚本
```

## 文件清单

| 文件 | 作用 |
|------|------|
| `SKILL.md` | 技能主定义：教学哲学、工作区规范、课程设计、锁定协议、最近发展区等完整流程 |
| `MISSION-FORMAT.md` | `MISSION.md` 的格式规范与规则（一工作区一使命、具体优于抽象、拒绝含糊） |
| `RESOURCES-FORMAT.md` | `RESOURCES.md` 的格式规范（只收录高可信来源、每条必须带注解） |
| `GLOSSARY-FORMAT.md` | `GLOSSARY.md` 的格式规范（用户理解后才收录、定义精简、标注需避免的别名） |
| `LEARNING-RECORD-FORMAT.md` | 学习记录格式与写入时机（非显而易见的关键洞见，非活动日志） |
| `DECISION-FORMAT.md` | ADR 决策记录格式，用于锁定长期不变的方向决策 |
| `HARNESS-TEMPLATE.md` | Harness 验证脚本模板：代码型（pytest/Jest）与概念型（固定 Q&A 题库） |
| `evals/evals.json` | 技能评测用例，覆盖新建工作区、知识型学习、继续已有学习三类场景 |
| `teachme-cn.zip` | 中文版本技能包压缩文件 |

## 核心流程

### 1. 建立工作区

读取 `SKILL.md`，先问清用户想学什么，创建或复用教学目录。所有路径均相对于该工作区根目录。

### 2. 明确使命

若 `MISSION.md` 为空或用户说不清目标，**先访谈用户**问清为什么想学。不理解使命，课程就会抽象，也无法判断下一步教什么。使命随学习演进而更新，变更前需与用户确认。

### 3. 获取知识

优先填充 `RESOURCES.md`，找高可信度资源（一手资料、公认专家、同行评审、强审核社区）。知识获取阶段**难度是敌人**。

### 4. 设计课程

每课为自包含 HTML，存入 `lessons/`，要求：美观耐看、简短且有具体收获、紧扣使命、引用一个最优质一手资料、末尾提醒用户可追问、与其他课程/参考文档用锚点链接互通。

### 5. 训练技能

通过测验与轻量浏览器内任务设计**紧密反馈循环**。测验中每个选项字数保持一致，避免长度暗示答案。技能训练阶段**难度是工具**——费力的回忆才建立存储强度。

### 6. 沉淀参考文档

参考文档是课程的压缩精华，为快速查阅而设计（语法片段、算法流程、体式序列、术语表等）。术语表是最基础的参考文档，一旦创建，所有课程都应遵守其定义。

### 7. 获取智慧

当用户提出需要智慧的问题时，默认尝试回答，但最终应引导其找到**高声誉社区**（论坛、subreddit、本地小组等）。用户不愿加入社区则尊重其意愿并记入 `RESOURCES.md`。

### 8. 验收与锁定协议（例外而非惯例）

用户确认某课程或里程碑"验收通过"后：

1. **判定**：是否存在**核心不变量**（核心公式、关键架构选择、数据格式约定等）。
2. **无核心不变量**（多数课程）：在 `NOTES.md` 中简记"课程 NNNN 验收通过"。
3. **有核心不变量**：
   - 向用户提案，明确需锁定的逻辑；
   - 用户确认后，按 `DECISION-FORMAT.md` 生成 ADR；
   - 按 `HARNESS-TEMPLATE.md` 生成验证脚本，存入 `harness/`。

Harness 只锁核心边界，不锁边缘细节；失败时必须暂停并提示用户是否废弃旧决策。

## Assets 组件复用

**复用是默认，不复用是例外。** 写新课前先读 `assets/`，用已有组件搭建。需要新的可复用元素时，写成组件放入 `assets/` 并链接引用，**绝不内联未来会重复的代码**。

每个工作区的第一个组件是一份**共享样式表**，所有课程链接它，让课程看起来是一套完整体系。

## 语言要求

所有回答及生成的文档（`MISSION.md`、`RESOURCES.md`、参考文档、课程内容等）均须使用**简体中文**，除非用户明确要求其他语言。
